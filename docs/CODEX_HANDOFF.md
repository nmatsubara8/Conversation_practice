## 作業を再開する場所

- GitHub は [nmatsubara8/Conversation_practice](https://github.com/nmatsubara8/Conversation_practice) の `main`。Windows の作業場所は `D:\applications\Conversation_practice`。
- NAS 上の運用ファイルは Windows の `X:\会話練習アプリ` に対応する。既存の Compose は NAS 側で管理し、GitHub には実環境の接続先や利用者データを保存しない。
- iPhone は Safari から Tailscale 限定の HTTPS でアクセスする。NAS は Web と faster-whisper `medium`（CPU）を実行する。Windows は Ollama `qwen3:14b` を実行する。Windows GPU 版 Whisper は比較用で、運用経路は NAS 版のまま。
- [README](../README.md) は Safari 版の導入、[Luanti の README](../integrations/luanti/README.md) は Windows の VoxeLibre 試作、[Whisper の README](../whisper/README.md) は CPU と GPU の比較。開発時の制約は [AGENTS.md](../AGENTS.md)。

今回、練習中に NAS（Whisper）を選んだ場合は **録音する → 話す → 録音を止める** の明示操作を追加した。自動録音はブラウザ側で音量と継続時間を判定し、Whisper 側でも VAD を使う。手動録音ではブラウザの自動判定を通さず、Web 経由の `X-Island-Manual: 1` で Whisper 側 VAD も外す。従来の「島に入る」から始まる場面の自動録音は残す。

## 確定した要件

### 言葉の獲得と会話の進行

- お互いの言語を知らない状態から始め、視線・指さし・身ぶり・物を動かす行為と短い発話で、対象と意味を確かめる。名前 → 物 → 場所は相手役が誘う順序。ユーザーは途中で別の概念を持ち込める。
- 自分を指しながら話せば自分の名前を確かめ、カメラを指しながら話せば相手への呼びかけとして扱う。確認後でも名前を何度でも訂正できる。物と場所は最初の PoC では画面で選ぶ。
- 「これ・あれ」は物、「ここ・そこ・あそこ」は場所。場所の言葉は、話し手と立ち位置を含めて確かめる。同じ場所でも話し手が替われば言い方が変わる。
- 学習・確認中、AI の通常発話は意味と使い方が共有済みの表現に限定する。新しい音はユーザーが対象を示し「音を聞く」を選んだときに提示する。例は水を指す → AI が `water` → ユーザーが「みず」→ AI が同じ水を指して「water、みず」→ ユーザーが合意。ここで二つの表現を暫定的に共有し、AI もユーザーの言葉を使う。
- 合意は AI が言い終えた後のうなずきか ✓。首振りか ✕ は再確認。反応がなければ待つ。相手が誤って空の器を「みず」と呼んだら、その結びつきを保留する。「コップ」だけを確定して先に進み、「みず」は後で確認してよい。無関係な記憶は維持する。
- 一度通じた表現を別の例に広げる場合、AI が対象を指して確認する。新しい例への否定は、以前通じた例の記録を消さない。訂正回数は無制限。
- 文法や語の組み合わせは単語とは別に確認する。「みず、ここ」なら、AI が水を持って台に置こうとする動作を見せる。合意してから、その使い方で発話できる。構成語を忘れた場合は組み合わせも再確認まで使わない。
- 発音が見本と違っても意味が通じれば会話を続け、AI が次に使うときに自然な音を聞けるようにする。ユーザーは必要なときに見本を求められる。

### 学習記録と振り返り

- 意味を共有した／見本なしで自分で使って通じた／AI のお願いを聞いて正しく行動できた、を別々に記録する。行動は対象・場所・動作ごとに判定する。お願いはまず声で伝え、必要時に指さしや動作を出す。声だけでできたか、身ぶりの助けがあったかを区別する。
- 会話中は点数や達成通知を出さない。日記や振り返り画面で日本語で確認できるようにする。
- NAS にテキストの日記を残す。セッションごとの要約と重要な発話を掲載し、会話の進行に合わせて更新する。終了ボタンを押さなくても残り、別端末で同じ会話を再開したら続きに追記する。画像・カメラ映像・音声は履歴に保存しない。
- AI のフリートーク原文は自動でテキスト履歴に残し、日記から開けるようにする。一文や語句を選んだときだけ日本語訳と説明を表示する。意味を調べたことだけで共有済み表現にはしない。日記の削除と、言葉の記憶の削除は別の操作。

### ユーザー・言語・キャラクター・NAS

- 家族はそれぞれ独立したプロフィール。端末での初回利用と利用者切替は本人の PIN で確認する。同じプロフィールの同時会話は 1 台。別端末で引き継ぐと旧端末は一時停止する。別プロフィール同士は同時に使える。
- 最終合意は **ユーザー × 対象言語** で意味と表現の記憶を管理すること。以前の「概念を言語横断で共有する」という案は見直した。別言語では、その言語の対象と表現の結びつきを確かめる。
- 同じユーザー・同じ言語なら、キャラクター間で合意・訂正・保留を共有する。相手役同士が伝聞で学んだ設定。話し手や立ち位置が変わる表現はその場で確かめる。別ユーザー間では共有しない。
- AI キャラクターはユーザーごとに自由に設定できる。相手役ごとに初期設定を用意し、話題を出す頻度、待つ長さ、身ぶりなどを調整できる。同じ名前・外見を別のユーザーが使っても別キャラクターとして扱う。
- 合意・訂正・保留と学習記録を NAS に自動保存する。切断時も会話を続け、端末が保存待ちを保持する。アプリを閉じても残し、同じ利用者で再開したとき再送する。別端末で同じ記憶が変更されていれば古い変更で上書きせず、再確認する。

### Luanti / VoxeLibre と自然な発話

- 現行 Safari PoC は、水とコップを区別し、台に水を置くお願いを理解する一場面。本実装は Luanti 上の VoxeLibre を使う前提。学習と世界の描画を分け、世界側は対象選択・配置などの操作を会話側に伝える。
- 浜辺で基本語彙と動作を確かめ、生活へ進む。必要な物を選ぶ、指定場所へ行く、止まる・戻るの合図に応じる、が支援付きでできれば相手役が短い探索に誘う。出発や帰還はユーザーが決める。
- AI は場面を見て身ぶり・声・案内を選ぶ。危険時は雑談を止め、危険を指し、共有済みの言葉と身ぶりで帰路を示す。移動操作はユーザーが行う。合意した目的の範囲では、AI は拾う・運ぶ・片づけるを自分で進める。ユーザーの物を使う、建物を壊す、建てる場合は合意を待つ。
- 移動や作業中のフリートークは、ヒアリングとリーディングの時間。AI の母語で、気分・性格・環境・状況に応じて自然に話す。共有語彙や文法に制限せず、同じ言語の字幕を出し、ユーザーの応答は求めない。頻度は相手役別に少なめ・標準・多め。
- 確認や危険への対応はフリートークより優先する。字幕の選択で意味確認へ移れる。敵が近い場合も原文は自動保存され、ユーザーに保存操作を求めない。字幕で選択していた文は安全になってから控えめに表示し、訳は本人が開いたときに出す。

| Windows GPU Whisper | 同じ WAV を CPU 版・GPU 版で測るコードと手順あり。Windows 実機の CUDA 動作、Ollama 同時利用、端末からの実測は未確認。 |

まず修正版で iPhone の「みず」を拾えることを確かめる。次に水・コップ・台を一巡し、依頼・聞いて行動・訂正まで確認する。Safari 版と VoxeLibre で会話状態を共有する前に、利用者と言語を単位にした NAS 保存を実装する。発話制約はコードで適用し、AGENTS.md に変更時の不変条件を書く。回帰テストでは未共有の表現が確認中の発話に入らないこと、フリートークとの切替、訂正後に古い言い方を使わないことを扱う。
